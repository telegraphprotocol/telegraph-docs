# Questions

## Can I work on an Issue that someone else claimed?

Usually, yes. Several contributors can claim the same normal bounty. Read the Issue first; established-provider opportunities use their own contact process.

## Do I get paid?

Only if the Issue has funded terms. `reward:unfunded` means no payment is promised. Read the Issue’s `## Reward` section before claiming.

## What should I submit?

The proof named in the Issue: typically a repository, live endpoint, demonstration, test output, or clear reproduction steps. A statement that something works is not sufficient.

## Can I put evaluation examples or customer requests in the Issue?

Only if they are explicitly authorized for public release. Keep hidden evaluation material, customer data, credentials, and private diagnostics in the authorized review channel.

## What if the Issue is unclear?

Ask a focused question in the Issue before claiming it. Do not guess the missing requirements.

## What if I find a security problem?

Use Telegraph’s private security-reporting channel. Do not post an exploitable detail on the bounty board.
