# Bounty Glossary

| Term | Meaning |
|---|---|
| **Acceptance criteria** | The observable conditions a maintainer must reproduce before accepting work. |
| **Bounty** | A public GitHub Issue describing a specific, reviewable gap. |
| **Claim** | A contributor’s recorded intention to work an Issue, made with `/claim`. |
| **Evaluator** | Logic that measures provider answers. Its protocol status is separate from GitHub. |
| **Intent** | A reusable kind of intelligence request in Telegraph. |
| **Material** | Publicly safe reference evidence or evaluation work, handled through the channel specified by the Issue. |
| **Miner / provider** | A service that can answer an Intent. |
| **Protocol eligibility** | The production/protocol decision that determines whether a provider or evaluator can participate. |
| **Reward** | The payment terms explicitly committed in an Issue, if any. |
| **Source label** | A label such as `source:h2` that records where a board need originated. |
| **Status label** | The board state: `triage`, `open`, `claimed`, `review`, `blocked`, or `done`. |
