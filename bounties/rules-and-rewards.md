# Rules and Rewards

## Rules

1. Work from a real, open Issue and meet its public acceptance criteria.
2. Claim only work you can actively deliver and keep updated.
3. Submit authentic, reproducible evidence. Do not invent demand, usage, results, or approval.
4. Keep private customer data, credentials, hidden evaluation material, private diagnostics, and security-sensitive details out of public work.
5. Use the private security channel for exploitable vulnerabilities.
6. Do not treat a GitHub status, merge, or comment as a protocol or production action.

## Rewards

`reward:unfunded` means no bounty payment is committed. A funded Issue must state the amount, denomination, payout asset, eligibility, verification condition, and payout window before it can be claimed.

When a claim is accepted, the board records a visible snapshot and hash of the Issue’s reward terms. That record is an audit aid; payment still requires the separate authorized funding and payout process.

Network incentives and bounty payments are separate systems. Completing or closing a GitHub Issue does not itself create protocol rewards, emissions, settlement, or eligibility.
